# Модуль рекомендаций

Онлайн-блок больше не показывает карточки вида `renewal`: продление остаётся отдельным сценарием кабинета. Апгрейд и дополнение остаются. Бэктест по-прежнему может поставить продление первым и всегда обрезает выдачу до трёх карточек. Онлайн может вернуть до 36 карточек. Пустая история берёт только популярность своей группы. Пустая отрасль и «Другое» отраслевой ключ не создают. Необязательный источник `SimilarItems` вызывается только онлайн. Ошибка источника оставляет каскад. Хранилище без этого метода просто пропускается.

```go
type SimilarItems interface {
    SimilarItems(ctx context.Context, snapshotID string, owned []domain.ItemID, limit int) ([]domain.Candidate, error)
}
```

Зелёные проверки этой ветки: `TestOnlineHidesRenewalAndKeepsUpgrade`, `TestOnlineCanReturnMoreThanThree`, `TestColdStartUsesOnlyTheClientGroup`, `TestSimilarItemsStayOnlineAndOptional`, плюс прежние `TestB2BSoloUsesCatalogComplement` и `TestOnlineDropsSameCategoryRival`.

# Модуль рекомендаций

Из корня Go-модуля выполните команду.

```sh
go test -count=1 -v ./internal/signals/... ./internal/recommend/...
```

В проверке на синтетике прошли `TestTrainCutoff`, `TestRecommendModule` и `TestRefillAfterFilters`. Онлайн у владельца DEMO-BASE не показывает продление. В историческом прогоне оба артикула продления по-прежнему занимают отдельные места.

## Сборка снимка

`signals.Build(ctx, meta, data, writer)` принимает метаданные `contract.Snapshot`, нормализованные `contract.DatasetBatch` и `contract.SnapshotWriter`. Неделя отсечения включительна. Популярность и поддержка измеряются числом разных покупателей. Балл корзины считает корзины по паре order_id и order_week одного заказа. Переход требует более поздней недели у того же покупателя. Балл Жаккара равен размеру пересечения покупателей, делённому на размер объединения. В снимке Candidate.Score содержит балл, Evidence.Weight — поддержку, Source — версию данных и алгоритма, SnapshotID — версию снимка. В один вызов PublishSnapshot передаются все рассчитанные поведенческие наборы.

Локальный CLI публикует JSON атомарной заменой файла. Минимальный пример из папки recsys использует синтетику.

```sh
work=$(mktemp -d)
cat > "$work/train.json" <<'JSON'
{"Snapshot":{"ID":"smoke","DatasetVersion":"synthetic","TrainThrough":"2026-08-31T00:00:00Z"},"Data":{"Clients":[{"ID":"u","Group":"B2C"}],"Sales":[{"OrderID":"1","ClientID":"u","ItemID":"base","OrderWeek":"2026-08-31T00:00:00Z"}]}}
JSON
go run ./cmd/build-signals -input "$work/train.json" -output "$work/snapshot.json"
```

## Подключение участниками 1, 3 и 4

`engine := recommend.New(reader)` реализует `contract.Recommender`. HTTP передаёт `contract.RecommendationQuery{ClientID: sessionClient, Mode: contract.Online}`. Оценщик задаёт `Mode: contract.Backtest` и явный `SnapshotID`. Обе стороны вызывают `engine.Recommend(ctx, query)`. Ошибки чтения возвращаются вызывающему коду.

Для PostgreSQL нужен адаптер `recommend.Reader`. К `contract.FactsReader` добавлены два чтения.

```go
SnapshotInfo(context.Context, string) (recommend.SnapshotInfo, error)
Products(context.Context, string, []domain.ItemID) (map[domain.ItemID]recommend.Product, error)
```

Пустой ID разрешается в активный снимок. Все запросы наборов и метаданных товаров используют уже разрешённый ID. History читает историю изолированного профиля, для бэктеста ограничивает её неделей TrainThrough. Profile возвращает группу и признаки клиента. При оценке нужно зафиксировать версию профилей в адаптере и отметить дату каталога и профилей в отчёте.

Products читает факты по item_id, включая исторические позиции без оффера. Для каждой требуемой позиции нужны строка метаданных, признак принадлежности к историческому множеству InSales и известные ограничения аудитории и платформы. Онлайн учитывается Available и наличие OfferID. При известных платформах покупок движок допускает товары с совпадающей или неопределённой платформой. Модуль 3 поставляет проверенные FamilyID, FamilySource и Differences с источниками. Оценщик может получить основание классификации через Products для рекомендованных и купленных артикулов того же снимка. При пустом FamilySource семейство считается неизвестным.

| CandidateKey.Signal | Остальные поля ключа | Источник |
|---|---|---|
| renewal, complement | SourceItemID купленного артикула | Подтверждённые связи модуля 3 |
| transition, jaccard, basket | SourceItemID купленного артикула | Расчёт signals.Build |
| popularity | ClientGroup и одна характеристика Industry, Segment или ClientType для B2B | Расчёт signals.Build |
| popularity | Только ClientGroup либо пустой ключ группы для общей популярности | Расчёт signals.Build |
| catalog | Пустые поля | Резервный список витрины |
| sales | Пустые поля | Резервный список из 817 исторических ID v4 |

Candidates возвращает стабильный префикс до limit по убыванию Score и далее по item_id. Неизвестный ключ даёт пустой список. Начальный лимит 64 увеличивается, если фильтры исчерпали префикс или в нём ещё могут быть более приоритетные товары. У каждого кандидата должно быть доказательство с уникальным ID, типом сигнала, причиной, источником и ID снимка. Для предметной связи From равен item:<исходный ID>, To всегда равен item:<рекомендуемый ID>. Для резервных наборов адаптер может использовать одинаковый балл и ребро от узла каталога или исторического ассортимента с причиной включения товара. Множество sales содержит только ID, сведения о будущих покупателях, датах и частотах в него не входят.

Стратегия сначала учитывает подтверждённое продление для B2B или дополнение для B2C. Далее идут переходы B2B, Жаккар, корзины, популярность в узких когортах, группе и общая популярность. Для отраслевого набора выбраны минимум пять различных покупателей train. Пустая отрасль и «Другое» пропускаются. Приоритет задаёт порядок сигналов, внутри уровня порядок определяют балл и item_id. Онлайн в одну карточку попадают варианты с подтверждённым семейством и одним видом рекомендации.

Проверки модуля работают в памяти. Подключение адаптера PostgreSQL, публикация каталожных доказательств и измерение метрик по закрытой базе v4 выполняются при общей сборке.
