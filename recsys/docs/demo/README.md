# Демо рекомендаций

Для витрины используется синтетическая БД со снимком `demo-v1`. Запустите базу, сервис рекомендаций, HTTP API и Vite по [инструкции проекта](../../../README.md). Откройте [главную страницу](http://localhost:5173/).

## Профили

После обычного `make seed` задайте `PREVIEW_ACCOUNT_PASSWORD` и `PREVIEW_ADMIN_PASSWORD` в окружении и из каталога `recsys` выполните:

```sh
go run ./cmd/seed -preview-accounts
```

Команда использует ту же строку подключения к синтетической БД, что и API. Повторный запуск обновляет пароли и отзывает сессии этих профилей.

| Логин | Статус |
| --- | --- |
| `notver` | Неверифицированный |
| `verb2b` | Верифицированный B2B |
| `verb2c` | Верифицированный B2C |
| `admin` | Администратор |

## Сценарий

1. Откройте главную без входа. «Популярные товары» показывает холодный старт для гостя. Для проверки холодного старта после входа используйте профиль `notver` без покупок.
2. Войдите как `verb2b`. В каждой новой сессии уже есть покупка `DEMO-BASE`. Проверьте апгрейд и дополнение, затем купите апгрейд и проверьте его исчезновение.
3. Откройте новую сессию с тем же логином. В ней снова доступны обе рекомендации. У `verb2c` отдельная исходная покупка `DEMO-B2C-1`, а граф показывает семантическую близость.
4. Войдите как `admin` и выберите профиль. Для тестового аккаунта открывается последний активный сеанс. В отладке видны снимок, оценки, граф, счётчики и прогоны.
5. В карточке открытого источника сравните состав тарифов Microsoft 365. Пример проверяет характеристику по странице Microsoft.

## Браузерный тест

Из каталога `frontend-softline` запустите `npm run test:e2e:demo`. С двумя переменными паролей тест обращается к живому API. Без них запросы перехватываются тестовыми ответами. Укажите `FRONTEND_URL` для другого адреса витрины и `CHROME_PATH` для конкретного Chromium.
