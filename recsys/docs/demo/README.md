# Демо личного кабинета

Демо на `/#/demo` использует синтетическую БД и API по [OpenAPI](../../api/openapi.yaml). Команды для запуска базы и API приведены в [README](../../README.md). Swagger доступен на `http://127.0.0.1:8080/swagger/`.

Запустите фронтенд из `frontend-softline`:

```sh
npm ci
npm run dev
```

На экране:

- карусель рисует все карточки ответа, но не больше 36; в метрику входят только первые три;
- главная кнопка объяснения открывает граф рёбер именно этой карточки в модальном окне (Escape, клик по фону или кнопка × в углу), текст «Почему рекомендуем» остаётся вторым;
- карточки с пометкой `status: "review"` визуально отделены и имеют бейдж «требует проверки», подтверждённые — бейдж «подтверждено»;
- профиль `demo-cold (без истории)` показывает синтетический пример без фразы о прошлой покупке;
- блок качества читает [публичные агрегаты v5](../../tests/e2e/data/public-metrics.json). Локальный [metrics.json](metrics.json) содержит запасные значения и подписи.
- дата фида берётся из `feed_generated_at` в ответе каталога, а при его отсутствии из локального файла. Она обозначает выгрузку фида, а фактические остатки меняются отдельно.

1. На `http://localhost:5173/#/demo` выберите `http (/api/v1)` и профиль B2B. Клиент выполнит настоящий вход и получит токен сессии.
2. В каталоге выберите базовую корпоративную лицензию `DEMO-BASE` и оформите покупку. В рекомендациях появятся апгрейд `DEMO-UPGRADE` и дополнительный модуль `DEMO-COMPLEMENT`.
3. Откройте «Почему рекомендуем». Граф апгрейда содержит направленное ребро от `DEMO-BASE` с источником связи.
4. Купите апгрейд. После обновления выдачи его карточка исчезнет, а дополнительный модуль останется.
5. Переключитесь на профиль B2C. Покупки первого аккаунта в его историю не попадают.

В чистой синтетике снимок — `demo-v1`. Локальный mock-транспорт показывает полную, частичную, пустую и ошибочную выдачи, а также пример проверки совместимости из JSON. Старые экраны `/#/` и `/#/recommendations` используют свои mock-данные по умолчанию. Для них прежний отладочный API не входит в текущий OpenAPI.

Перед первым браузерным E2E используйте чистую демо-БД. Из `frontend-softline` выполните `npm run test:e2e:demo`. Для реальной покупки установите `RECSYS_E2E_LIVE=1` и задайте `FRONTEND_URL`, `RECSYS_E2E_API` при нестандартных портах. `VITE_PROXY_RECSYS_TARGET` передаётся при запуске Vite. Для выбранного браузера можно задать `CHROME_PATH`.

Все результаты прогона и ограничения приведены в [INTEGRATION.md](INTEGRATION.md).
