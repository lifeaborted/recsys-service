# Демо личного кабинета

Демо на `/#/demo` использует синтетическую БД и семь операций [OpenAPI](../../api/openapi.yaml). Команды для запуска базы и API приведены в [README](../../README.md). Swagger доступен на `http://127.0.0.1:8080/swagger/`.

Запустите фронтенд из `frontend-softline`:

```sh
npm ci
npm run dev
```

На экране:

- карусель рисует все карточки ответа, но не больше 36; в метрику входят только первые три;
- главная кнопка объяснения открывает граф рёбер именно этой карточки в модальном окне (Escape, клик по фону или «Закрыть»), текст «Почему рекомендуем» остаётся вторым;
- карточки с пометкой `verification: "requires_check"` визуально отделены и имеют бейдж «требует проверки», подтверждённые — бейдж «подтверждено»;
- профиль `demo-cold (без истории)` показывает синтетический пример без фразы о прошлой покупке;
- блок качества читает [metrics.json](metrics.json): таблица A/B × все/B2B/B2C, под ней полосы сравнения A и B, доля вариантов гибрида, отдельная строка про 55% визитов, дата фида и оговорка об отсутствии исторического снимка каталога. Пока числа помечены `"provisional": true`.

1. На `http://localhost:5173/#/demo` выберите `http (/api/v1)` и профиль B2B. Клиент выполнит настоящий вход и получит токен сессии.
2. В каталоге выберите базовую корпоративную лицензию `DEMO-BASE` и оформите покупку. Найдите карточку продления и раскройте варианты. Доступны отдельные `DEMO-RENEW-12` и `DEMO-RENEW-24`.
3. Откройте «Почему рекомендуем». У обоих вариантов есть направленные рёбра от `DEMO-BASE` со ссылками на источники.
4. Купите вариант на 12 месяцев. После обновления выдачи купленный ID исчезнет из карточек и вложенных вариантов.
5. Переключитесь на профиль B2C. Покупки первого аккаунта в его историю не попадают.

В чистой синтетике снимок — `demo-v1`. Локальный mock-транспорт показывает полную, частичную, пустую и ошибочную выдачи, а также пример проверки совместимости из JSON. Старые экраны `/#/` и `/#/recommendations` используют свои mock-данные по умолчанию. Для них прежний отладочный API не входит в текущий OpenAPI.

Перед первым браузерным E2E используйте чистую демо-БД. Из `frontend-softline` выполните `npm run test:e2e:demo`. Для реальной покупки установите `RECSYS_E2E_LIVE=1` и задайте `FRONTEND_URL`, `RECSYS_E2E_API` при нестандартных портах. `VITE_PROXY_RECSYS_TARGET` передаётся при запуске Vite. Для выбранного браузера можно задать `CHROME_PATH`.

Все результаты прогона и ограничения приведены в [INTEGRATION.md](INTEGRATION.md).
