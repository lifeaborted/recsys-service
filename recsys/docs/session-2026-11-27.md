## Этот пуш

Онлайн-фильтр конкурентов. Другой вендор в той же `category_id`, что уже есть у покупателя, в онлайн-выдачу не попадает. Пример: Kaspersky не предлагает Dr.Web. В данных такой разметки нет: вендор берётся из `catalog_vendors` / `catalog_version_offers`, категория из оффера. Пустой вендор или пустая категория фильтр не включают. Renewal, upgrade и complement не режутся. Бэктест фильтр не применяет.

Онлайн-перестановка короткого списка. Если заданы `LLM_BASE_URL` и `LLM_MODEL`, `cmd/api` вешает на движок `explain.Chat`. Модель может только переставить уже отобранные id (голова до 8 карточек). Новые товары она не добавляет. Ошибка или 8 секунд молчания оставляют порядок каскада. Бэктест перестановку не вызывает. На этой машине локальная чат-модель отвечает около 25 секунд, поэтому текущий процесс API поднят без `LLM_*`: иначе каждый запрос ждал бы таймаут и всё равно возвращал каскад.

Векторы фида. `cmd/embed-catalog` пишет доступные офферы с ценой больше нуля в `recommendations.catalog_offer_embeddings`. Колонка без фиксированной размерности, пока не известна модель; после загрузки она становится `vector(N)` и строится HNSW по косинусу. Повторный запуск пропускает уже сохранённые `offer_id`. Поиск по этой таблице: `cmd/enrich -vector-index` (нужен `DATABASE_URL` с расширением `vector`). Старый `-semantic-search` по-прежнему считает маленький одобренный фид в памяти.

Прогон на этой машине уже сделан: 44 450 офферов, Qwen3-Embedding-0.6B, размерность 1024. Колонка `catalog_version_offers.embedding vector(1536)` для этой модели не используется. Кластер с дампом v5 собран без pgvector, поэтому векторы лежат в локальном контейнере `recsys-vector` (`127.0.0.1:55433`), а не в базе API. Образ тот же, что в `compose.yml`. Чужой машине этот контейнер не виден: команда `embed-catalog` нужна ещё раз на стенде с pgvector.
